The Core Mental Model (Very Important)

Object creation in Python has TWO distinct phases:

Creation → __new__

Initialization → __init__

Most developers only ever touch phase 2.

1️⃣ __new__ — “Do I even create this object?”
What it is

A class method (even though it doesn’t look like one)

Responsible for creating the object

Must return an instance

Signature
def __new__(cls, *args, **kwargs):
    return super().__new__(cls)

Key properties

Runs before __init__

Controls:

Whether an object is created

What object is returned

Can return:

An instance of cls

An instance of another class

An existing instance (singleton)

Even None (then __init__ is skipped)

📌 If __new__ doesn’t return an instance of cls, __init__ is never called.

2️⃣ __init__ — “Now that it exists, set it up”
What it is

An initializer, NOT a constructor

Receives an already-created object

Returns nothing

Signature
def __init__(self, arg1, arg2):
    self.arg1 = arg1
    self.arg2 = arg2

Key properties

Runs after __new__

Only initializes state

Cannot prevent object creation

Timeline (This Should Be Burned Into Memory)
Class() call
   ↓
__new__(cls)
   ↓
(instance created)
   ↓
__init__(self)

Why 99% of Classes Don’t Need __new__

Because Python already knows how to create objects.

So for normal classes:

class User:
    def __init__(self, name):
        self.name = name


Python internally does:

obj = object.__new__(User)
User.__init__(obj, name)


You only override __new__ when creation itself must change.

When You MUST Use __new__ (Real Use Cases)
1️⃣ Singleton (as shown in the video)
class Language:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance


✔ Same instance returned every time
✔ __init__ may run multiple times unless guarded

2️⃣ Immutable Types (VERY IMPORTANT)

Built-ins like int, str, tuple use __new__ because:

You cannot modify them after creation.

class MyInt(int):
    def __new__(cls, value):
        return super().__new__(cls, value * 2)

x = MyInt(10)
print(x)  # 20


🚨 __init__ would be too late here.

3️⃣ Object Caching / Flyweight Pattern
class CachedUser:
    _cache = {}

    def __new__(cls, user_id):
        if user_id not in cls._cache:
            cls._cache[user_id] = super().__new__(cls)
        return cls._cache[user_id]


Same user_id → same object.

4️⃣ Returning Different Classes
class Shape:
    def __new__(cls, kind):
        if kind == "circle":
            return Circle()
        if kind == "square":
            return Square()


Factory behavior at creation time.

One Dangerous Trap (Advanced)
class A:
    def __new__(cls):
        return "hello"

    def __init__(self):
        print("init")

a = A()
print(a)


Output:

hello


🚫 __init__ is never called
🚫 Object is not instance of A

Golden Rules (Memorize These)

__new__ creates

__init__ configures

If you don’t need to change creation → don’t touch __new__

If the object is immutable → you must use __new__

__init__ cannot stop object creation

__new__ can return anything

One-Line Summary (Interview-Grade)

__new__ controls whether and how an object is created, while __init__ only initializes an already-created object.
